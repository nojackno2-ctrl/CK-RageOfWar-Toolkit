# 遊戲內建的開發者主控台

**結論：主控台不需要開啟，出廠設定就是啟用的。** 按 **Enter** 叫出輸入列。

以下是逆向過程與依據。

## config.ini 已經把它打開了

`config.ini` 是 `LZIS` 壓縮容器，解開後（見下方工具）內容是：

```ini
[system]
WindowX = 1024
WindowY = 768
NoException = 0
NoSplash = 0
LogFile = logs/vxlog.log
ScriptCompileStats = logs/comp_out.txt
VisibleDestLocks = 0
DebugKeys = 1          ← 已啟用
Console = 1            ← 已啟用
FormationLog = 0
MainMenu = 1
AIEnabled = 1
SinglepalyerMap = Adventures/tutorial
DefaultPlayerName = Noname
NewPF = 1
RequiredFile = guid.dat
```

完整內容見 [config.ini.decompressed.txt](config.ini.decompressed.txt)。

`Console` 綁定到全域變數 `0x74C3D0`，`DebugKeys` 綁 `0x74C3CC`；兩者在
執行檔的 `.data` 區初始值也都是 `1`。也就是說，不論 config.ini 有沒有設，
預設都是開的。

## 怎麼叫出來

`Celtic kings.exe` 的鍵盤處理（VA `0x47D39B` 起）：

```asm
cmp  ax, 0x0D              ; VK_RETURN
jne  ...                   ; 不是 Enter 就跳過
call GetKeyState(0x10)     ; VK_SHIFT
jne  ...                   ; Shift 按著就不處理
call GetKeyState(0x12)     ; VK_MENU (Alt)
jne  ...                   ; Alt 按著就不處理
mov  eax, [0x74C3D0]       ; Console 旗標
je   ...                   ; 為 0 就不處理
...                        ; 配置輸入列物件
call GetKeyState(0x11)     ; VK_CONTROL —— 當成參數傳給輸入列
call 0x59F1F0              ; 建立輸入列
```

所以：**遊戲中按 Enter（不要按住 Shift 或 Alt）**。Ctrl 有沒有按著會被
當成參數傳進去（存到 `0x8AABCC`），我沒有追到它確切的作用，Enter 沒反應
的話可以試試 Ctrl+Enter。

## 輸入的內容會被當成腳本執行

主控台的處理常式（`0x5E73xx`–`0x5EB0xx`）有這幾個已確認的指令字串：

| 指令 | 說明 |
|---|---|
| `pr <運算式>` | 印出運算式的值 |
| `cls` | 清除主控台輸出 |
| `watch <運算式>` | 持續監看。以簽章 `str OUT, Obj this` 編譯，對物件求值 |

其餘輸入會送進腳本編譯器（`0x5E0340`）執行。`Basicgame::Prompt` 這條路徑
會在輸入後面補上 `();` 再編譯，所以只打函式名稱應該就會被當成呼叫。

輸出以捲動文字顯示在畫面上，停留時間由 `vxConst.ini` 的 `ConsoleScrollTime`
（預設 5000 毫秒）決定——這也是修改器熱鍵訊息顯示的同一個地方。

## 主控台裡可用的函式

執行檔內註冊了一整組全域函式，作弊相關的包括：

```
ExploreAll        ToggleFog         SetPlayer          CurPlayer
Place(cls,x,y,player)               _Summon            Spawn(our,enemy)
GetItem(itemID)   _PlayersAlly      _PlayersMakeEnemies
_PlayersShareView _PlayersShareControl                 _PlayersShareSupport
GetSpeed/SetSpeed Pause             _SetNextSeason     ReloadConstIni
MakePassable      selu/selb/sels    DumpFuncToXML      pr / cls / watch
```

其中部分函式會回報 `[error] Accessible only in *editor* mode`，那些要用
`Celtic kings.exe -edit` 進編輯器才能用。

腳本語法與型別見 [VS腳本速查.md](VS腳本速查.md)。

## 解壓縮工具

[`tools/lzis_decompress.py`](../tools/lzis_decompress.py)。它不重寫演算法，
而是把 `Celtic kings.exe` 載入 Unicorn 模擬器、直接呼叫遊戲自己的解壓縮
函式 `0x417340`，把配置器接管掉後取回結果。

```bash
py -m pip install unicorn
py tools/lzis_decompress.py "…/CK_RageOfWar/config.ini" out.ini
```

### LZIS / LZSS 容器格式

```
0x00  magic "LZIS" 或 "LZSS"
0x04  u32  未壓縮總長度
0x08  u32  區塊大小（實測 0x8000）
0x0C  u8   壓縮等級（LZIS 1~3；config.ini 是 2）
0x0D  u8   保留
0x0E  u32[] 區塊位移表，table[0] 就是壓縮資料的起始位移
```

解壓縮函式原型是 `int decompress(void* src, int srcLen, void* dst, int* len)`，
`*len` 傳入時是輸出緩衝區容量、傳回時是實際長度，回傳 0 代表成功。

演算法本身是 bit-level 的 LZ 加 Huffman（會配置 0x8F0 與 0x1E0 兩張表、
用 `bswap` 做大端位元讀取）。我沒有把它完整還原成獨立實作——用模擬器直接
執行原始碼比較可靠，也不會因為猜錯參數而產出看似正確的錯誤結果。

## 純文字設定檔一樣讀得進去

檔案工廠（`0x4186E0`）在讀進前 4 個位元組後：magic 是 `LZSS` 就包一層
`CLzssFile`、是 `LZIS` 就包 `CLzisFile`，**兩者都不是就倒回檔頭、直接
使用原始檔案**：

```asm
00418796  mov  edx, [esi]
00418798  push 0
0041879A  push 0
0041879C  mov  ecx, esi
0041879E  call [edx + 0x1c]      ; Seek(0, 0)
004187A1  pop  edi
004187A2  mov  eax, esi          ; 直接回傳未包裝的原始檔案
```

所以要改設定，把 [config.ini.decompressed.txt](config.ini.decompressed.txt)
改一改、以 `config.ini` 之名放回遊戲目錄即可，**不需要重新壓縮**。改之前
記得備份原本的 `config.ini`。

## 順帶發現：[mount] 區段

解開的 config.ini 裡有整張虛擬檔案系統掛載表：

```ini
[mount]
data/= pack,data.pak
local/= pack,local.pak
assets/minimap/=pack,minimap.pak
gameini/=trans,data/interface/
gameres/=trans,assets/interface/
...

[Patches]
patch1.pak
```

`pack` 是掛 pak，`trans` 是轉址到真實資料夾。這代表除了改寫 `data.pak`
之外，理論上還能加一條 `trans` 掛載、讓散檔覆蓋 pak 內容——那會是比重新
打包更輕量的改法。修改器目前沒有用這條路，因為掛載優先序還沒驗證過。
